# Setup

Use the owner's chosen folder directly as the collection, including when it is a repository root. The skill supplies the method; collection guidance belongs to its local owner.

## Agree the scope

Inspect the chosen directory and enclosing Git worktree. Confirm the remaining choices in one short batch:

- Collection path, owner and intended readers.
- Who may contribute, with what authorization and disclosure rules.
- Whether to use Git and which operations are authorized.
- Where private local instructions and followed collection locations belong.

Check actual storage permissions through the provider's existing access procedures. Establish the audience of a synced folder before writing into it. Agree the setup or migration changes before applying them.

## Collection guidance

For a new collection, create its folder and a short `README.md` using confirmed facts:

```markdown
# <Collection name>

Messages for <audience>.
Owner: <person or team>.
Location: <collection location>.
Contribution rules: <who may contribute and the applicable authorization rules>.

Use the Works skill to retain, retrieve and share messages.
```

Include the applicable fields and a link to the installed skill where practical. Create message folders as material is captured.

Preserve existing records and their addresses when updating a collection's guidance. Retain location declarations needed to interpret references in existing messages. Agree changes to locally owned instructions with their owner.

## Personal instructions

Use an applicable existing `AGENTS.md` for local execution rules, private followed locations and access notes. Where one is needed, agree its location and keep it short:

```markdown
# Local instructions

Load the installed Works skill for this collection.
This file is maintained by its owner.

<Local execution and disclosure rules, collection locations and access notes.>
```

Keep personal details in storage appropriate to their audience. Other collections' owners determine their structures, access and contribution rules; their locations can be retained as starting points for task-driven retrieval.

## Apply and confirm

Apply the agreed file changes and authorized Git operations. Preserve the owner's privacy and retention rules. For shared changes, verify the result through the intended recipient's access route. Report the changed locations and any access questions that remain.
